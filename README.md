# 顔の好み診断

2枚の顔から「好きなほう」を選ぶ操作を繰り返して、**自分がどんな顔をタイプだと感じているか**を診断する Web アプリです。

輪郭・目の大きさ・タレ目/ツリ目・眉・鼻・口・髪など **15項目**について、
「どの特徴をどれだけ重視して選んでいたか」と「その特徴のどのあたりが好みか」を推定します。

- ビルド不要（素の HTML + ES モジュール）
- 実行時の外部通信なし（顔画像も推定処理もすべてローカル）
- スマートフォン対応・ダークモード対応

---

## 仕組み

### 1. 顔画像に特徴量を紐づける

「どんな顔が好きか」を言葉で言い当てるには、画像そのものではなく**画像の特徴が数値化されている**必要があります。
そこで取り込み時に [face-api](https://github.com/vladmandic/face-api) で顔検出・68点ランドマーク・年齢/性別推定を行い、
両目間の距離で正規化した幾何量（顔の縦横比、目の開き、目尻の傾き、眉と目の距離、小鼻の幅、唇の厚みなど）と、
画素統計（肌の明るさ、髪の明るさ、髪の長さ）を実測して `data/faces.json` に保存します。

絶対値のままでは「大きい/小さい」の基準が決まらないため、アプリ側で**プール内の順位**に変換し、
すべての特徴を 0.0〜1.0 の相対値にそろえます（`src/features.js`）。

### 2. 選択から好みを推定する

特徴 k について理想値 `m_k` と重視度 `s_k` があると考え、顔 x の好ましさを

```
u(x) = -Σ_k s_k (x_k - m_k)²
```

とする**理想点モデル**を使います。2択の勝率は `P(A) = sigmoid(u(A) - u(B))` で、
これを比較データから MAP 推定します（`src/model.js`）。

単純な重み付き和ではなく理想点モデルを使うのは、

- 「大きすぎても小さすぎても嫌、中くらいが好き」という好みを表現できる
- 重視していない特徴は `s_k` がほぼ 0 に落ちるので、**こだわりの有無を分離できる**

ためです。

### 3. 出す2枚を選ぶ

ランダムに2枚出すと15項目すべてが同時に違ってしまい、どの特徴が効いたのか分離できません。
そこで毎回、候補ペアの中から

- まだ観測の薄い特徴で差がついている
- すでに分かった特徴では差が小さい
- 現在のモデルの予測が五分五分（＝情報量が大きい）
- 同じ顔が出すぎていない

ものを選びます。

シミュレーション（`npm test`）では、この選び方でランダム出題より明確に精度が上がりました。

| 出題方法 | 20回 | 30回 | 45回 |
|---|---|---|---|
| ランダム | 73.6% | 78.5% | 83.6% |
| 適応的（本アプリ） | **77.7%** | **83.0%** | **86.0%** |

数値は、好みを持つ仮想ユーザーに選ばせ、その回答だけから推定したモデルが
**未知のペアで仮想ユーザーの好みを当てられた割合**です（60試行の平均）。

## セットアップ

### 1. 依存をインストール

```bash
npm install
```

アプリ本体に依存はありません。ここで入るのは画像の生成・解析ツール用です。

### 2. 顔画像を用意する

**実在の人物ではなく、AI が生成した架空の顔を使うことを推奨します。**
実在する人の顔を「好み」で採点させるアプリになることを避けるためです。

#### A. Gemini / Imagen API で生成する

```bash
GEMINI_API_KEY=xxxx npm run generate -- --count 160 --out .cache/raw
```

APIキーは [Google AI Studio](https://aistudio.google.com/apikey) で取得できます。

診断の精度は**プールが特徴空間をどれだけ広くカバーするか**で決まるため、
輪郭・目・眉・鼻・唇・髪・肌・年齢の属性グリッドから均等に組み合わせを引いてプロンプトを作ります。
肌の色や髪の長さの実測を安定させるため、構図と背景は全カットで固定しています。

| オプション | 既定値 | 説明 |
|---|---|---|
| `--count` | 160 | 生成枚数 |
| `--model` | `imagen-4.0-fast-generate-001` | `--list-models` で利用可能なモデルを確認できます |
| `--ethnicity` | `mixed` | `eastasian` / `mixed` / `global` |
| `--female-ratio` | 0.5 | 女性の割合 |
| `--dry-run` | – | 課金せずプロンプトだけ確認 |

生成は途中で止めても、再実行すれば既存ファイルを飛ばして続きから進みます。

#### B. 他のツールで作った画像を使う

ComfyUI / Stable Diffusion / DALL·E など、**どのツールの出力でも構いません**。
画像を1つのフォルダにまとめて、次の解析手順に渡してください。
`A` と同じ構図（正面・無地の背景・頭と肩が入る）で作ると、髪や肌の実測が安定します。

### 3. 解析して取り込む

```bash
npm run analyze -- --from .cache/raw
```

`data/faces/*.jpg`（顔を中心にそろえた正方形）と `data/faces.json`（特徴量）が作られます。
顔が検出できない画像、顔が端に寄りすぎている画像は自動的に除外されます。

| オプション | 既定値 | 説明 |
|---|---|---|
| `--from` | （必須） | 入力画像フォルダ |
| `--size` | 480 | 書き出す画像の一辺 |
| `--append` | – | 既存の `faces.json` に追加する |
| `--limit` | 制限なし | 先頭 N 枚だけ処理する |

12枚あれば起動しますが、**150枚以上**あると診断が安定します。

### 4. 起動

```bash
npm start
# http://localhost:5173/
```

静的ファイルなので、GitHub Pages など任意の静的ホスティングにそのまま置けます。

## 画像がなくても動作を試す

ダミーの顔プールを作って、アプリの流れだけ確認できます。

```bash
node test/fixture.mjs
npm start
# http://localhost:5173/?data=.cache/fixture
```

`?data=` で顔プールを差し替えられます。

## ファイル構成

```
index.html          画面
styles.css          スタイル
src/features.js     15項目の定義と、プール内順位への正規化
src/model.js        理想点モデルの推定・出題ペアの選択
src/app.js          画面遷移と診断の進行
tools/generate.mjs  Gemini / Imagen での顔生成
tools/analyze.mjs   顔検出・特徴量の実測・切り出し
tools/serve.mjs     依存ゼロの静的サーバー
test/simulate.mjs   仮想ユーザーによる推定精度の検証
test/fixture.mjs    ダミー顔プールの生成
data/faces.json     解析結果（生成される）
data/faces/         顔画像（生成される）
```

## 注意

- 診断結果はエンターテイメントとして作られたものです。15項目・数十回の選択から推定した傾向にすぎません。
- 結果はブラウザの localStorage にのみ保存され、どこにも送信されません。
- 生成した顔画像の利用条件は、使用した生成サービスの規約に従ってください。
