# 顔の好み診断

2枚の顔から「好きなほう」を選ぶ操作を繰り返して、**自分がどんな顔をタイプだと感じているか**を診断する Web アプリです。

輪郭・目の大きさ・タレ目/ツリ目・眉・鼻・口・髪など **15項目**について、
「どの特徴をどれだけ重視して選んでいたか」と「その特徴のどのあたりが好みか」を推定します。

- ビルド不要（素の HTML + ES モジュール）
- 実行時の外部通信なし（顔画像も推定処理もすべてローカル）
- スマートフォン対応・ダークモード対応

---

## 仕組み

### 1. 顔画像に特徴量を紐づける

「どんな顔が好きか」を言葉で言い当てるには、画像そのものではなく**画像の特徴が数値化されている**必要があります。
そこで取り込み時に [face-api](https://github.com/vladmandic/face-api) で顔検出・68点ランドマーク・年齢/性別推定を行い、
両目間の距離で正規化した幾何量（顔の縦横比、目の開き、目尻の傾き、眉と目の距離、小鼻の幅、唇の厚みなど）と、
画素統計（肌の明るさ、髪の明るさ、髪の長さ）を実測して `data/faces.json` に保存します。

絶対値のままでは「大きい/小さい」の基準が決まらないため、アプリ側で**プール内の順位**に変換し、
すべての特徴を 0.0〜1.0 の相対値にそろえます（`src/features.js`）。

### 2. 選択から好みを推定する

特徴 k について理想値 `m_k` と重視度 `s_k` があると考え、顔 x の好ましさを

```
u(x) = -Σ_k s_k (x_k - m_k)²
```

とする**理想点モデル**を使います。2択の勝率は `P(A) = sigmoid(u(A) - u(B))` で、
これを比較データから MAP 推定します（`src/model.js`）。

単純な重み付き和ではなく理想点モデルを使うのは、

- 「大きすぎても小さすぎても嫌、中くらいが好き」という好みを表現できる
- 重視していない特徴は `s_k` がほぼ 0 に落ちるので、**こだわりの有無を分離できる**

ためです。

### 3. 出す2枚を選ぶ

ランダムに2枚出すと15項目すべてが同時に違ってしまい、どの特徴が効いたのか分離できません。
そこで毎回、候補ペアの中から

- まだ観測の薄い特徴で差がついている
- すでに分かった特徴では差が小さい
- 現在のモデルの予測が五分五分（＝情報量が大きい）
- 同じ顔が出すぎていない

ものを選びます。

シミュレーション（`npm test`）では、この選び方でランダム出題より明確に精度が上がりました。

| 出題方法 | 20回 | 30回 | 45回 |
|---|---|---|---|
| ランダム | 73.6% | 78.5% | 83.6% |
| 適応的（本アプリ） | **77.7%** | **83.0%** | **86.0%** |

数値は、好みを持つ仮想ユーザーに選ばせ、その回答だけから推定したモデルが
**未知のペアで仮想ユーザーの好みを当てられた割合**です（60試行の平均）。

## セットアップ

### 1. 依存をインストール

```bash
npm install
```

アプリ本体に依存はありません。ここで入るのは画像の生成・解析ツール用です。

### 2. 顔画像を用意する

**実在の人物ではなく、AI が生成した架空の顔を使うことを推奨します。**
実在する人の顔を「好み」で採点させるアプリになることを避けるためです。

#### A. Gemini / Imagen API で生成する

```bash
GEMINI_API_KEY=xxxx npm run generate -- --count 160 --out .cache/raw
```

APIキーは [Google AI Studio](https://aistudio.google.com/apikey) で取得できます。

> **Gemini の画像生成には課金の有効化が必要です。**
> 画像生成モデルには無料枠が存在せず（料金表の無料枠欄が「利用不可」）、
> 無料枠のプロジェクトからは `limit: 0` のエラーになって1枚も生成できません。
> AI Studio の "Set up Billing" から有効化してください。
> なお AI Studio の画面上での生成は無料ですが、API経由とは別枠です。
> 課金を有効にしたくない場合は、後述の **B** の方法で他のツールの出力を取り込めます。

料金は出力解像度で変わります。このアプリは取り込み時に 480px へ縮小するため、
既定では最小の `0.5K` を指定しています。

| 解像度 | 1枚あたり | 160枚 |
|---|---|---|
| 0.5K（既定） | $0.045 | 約 $7 |
| 1K | $0.067 | 約 $11 |

（入力プロンプトは1枚あたり約120トークンで、合計しても1セント未満です。
最新の単価は[料金ページ](https://ai.google.dev/gemini-api/docs/pricing)を確認してください。）

診断の精度は**プールが特徴空間をどれだけ広くカバーするか**で決まるため、
輪郭・目・眉・鼻・唇・髪・肌・年齢の属性グリッドから均等に組み合わせを引いてプロンプトを作ります。
肌の色や髪の長さの実測を安定させるため、構図と背景は全カットで固定しています。

| オプション | 既定値 | 説明 |
|---|---|---|
| `--count` | 160 | 生成枚数 |
| `--model` | `gemini-3.1-flash-image` | 利用可能なモデルは `npm run generate -- --list-models` で確認できます |
| `--image-size` | `0.5K` | 出力解像度。モデルが受け付けない場合は自動で指定を外して続行します |
| `--ethnicity` | `mixed` | `eastasian` / `mixed` / `global` |
| `--female-ratio` | 0.5 | 女性の割合 |
| `--dry-run` | – | 課金せずプロンプトだけ確認 |

生成は途中で止めても、再実行すれば既存ファイルを飛ばして続きから進みます。
レート制限は自動で待って再試行します。

#### A-2. AI Studio の画面で手作業で生成する（無料）

API を使わず、AI Studio の画面上で生成する場合はプロンプト一覧を書き出せます。

```bash
npm run generate -- --dry-run --count 24 --female-ratio 1 --out .cache/raw
```

2種類のプロンプトが書き出されます。

| ファイル | 用途 |
|---|---|
| `prompts.txt` | 1件ずつ完結したプロンプト。1回ごとに貼り付ける場合 |
| `prompts-chat.txt` | 共通条件を最初に1回送り、以降は1行ずつ送る形式。**スマホ向け** |

スマホで長文を毎回貼り付けるのは大変なので、その場合は `prompts-chat.txt` を使ってください。
「4人を2x2に並べた1枚」を作らせて `--multi` で取り込めば、生成回数をさらに減らせます
（1人あたりの解像度は下がります）。

`--female-ratio 1` で女性のみ、`0` で男性のみになります。
アプリは片方の性別だけで12枚以上必要なので、**まずは診断したい側の性別だけ**を集めるのが確実です。

生成した画像を1つのフォルダに保存したら、通常どおり解析してください。
1枚の画像に複数人を生成させた場合は `--multi` を付けると全員を個別に取り込めます。

**スクリーンショットではなく画像そのものを保存してください。** 画面の余白やUIが写り込むと
背景が無地でなくなり、「髪の長さ」が計測できなくなります。

対応形式は jpg / png / webp / heic / heif / tiff / gif です。ただし
iPhone のカメラ形式である HEIC(HEVC) は sharp の標準ビルドでは読めないため、
その場合は JPEG に変換してから渡してください。
（ブラウザやアプリから保存した生成画像は通常 PNG か JPEG なので、多くの場合は問題になりません。）

#### B. 他のツールで作った画像を使う

ComfyUI / Stable Diffusion / DALL·E など、**どのツールの出力でも構いません**。
画像を1つのフォルダにまとめて、次の解析手順に渡してください。
`A` と同じ構図で作ると実測が安定します。特に次の2点は計測の前提です。

- **正面向き** — 顔が大きく傾いたり横を向いていると、ランドマークの精度が落ちます。
- **無地の背景** — 「髪の長さ」は *髪色に近く、背景でも肌でもない画素が、あごより下にどれだけあるか* で測るため、
  背景が雑多だと髪と背景を分離できません。四隅の色がばらついている画像では、
  この項目を**計測不能として除外**します（他の項目は影響を受けません）。

### 3. 解析して取り込む

```bash
npm run analyze -- --from .cache/raw
```

`data/faces/*.jpg`（顔を中心にそろえた正方形）と `data/faces.json`（特徴量）が作られます。
顔が検出できない画像、顔が端に寄りすぎている画像は自動的に除外されます。
実行後に項目ごとの実測値のばらつきが表示されるので、特定の項目だけ差がついていない、
あるいは計測不能が多い、といった異常にすぐ気づけます。

| オプション | 既定値 | 説明 |
|---|---|---|
| `--from` | （必須） | 入力画像フォルダ |
| `--size` | 480 | 書き出す画像の一辺 |
| `--append` | – | 既存の `faces.json` に追加する |
| `--limit` | 制限なし | 先頭 N 枚だけ処理する |
| `--multi` | – | 1枚の画像に写っている顔を全員取り込む（既定は最も確からしい1人だけ） |
| `--debug` | – | 検出したランドマークと肌/髪の採取位置を重ねた確認用画像を出力する |

計測が意図どおりか疑わしいときは `--debug .cache/debug` を付けて、
書き出された画像でランドマークと採取位置（水色=肌、黄=髪、破線=あごの位置）を目で確認してください。

12枚あれば起動しますが、**150枚以上**あると診断が安定します。

### 4. 起動

```bash
npm start
# http://localhost:5173/
```

静的ファイルなので、GitHub Pages など任意の静的ホスティングにそのまま置けます。

node test/fixture.mjs

# http://localhost:5173/?data=.cache/fixture

## ファイル構成

```
index.html          画面
styles.css          スタイル
src/features.js     15項目の定義と、プール内順位への正規化
src/model.js        理想点モデルの推定・出題ペアの選択
src/app.js          画面遷移と診断の進行
tools/generate.mjs  Gemini / Imagen での顔生成、手作業用プロンプトの書き出し
tools/analyze.mjs   顔検出・特徴量の実測・切り出し
tools/serve.mjs     依存ゼロの静的サーバー
test/simulate.mjs   仮想ユーザーによる推定精度の検証
test/fixture.mjs    ダミー顔プールの生成
data/faces.json     解析結果（生成される）
data/faces/         顔画像（生成される）
```

## 注意

- 診断結果はエンターテイメントとして作られたものです。15項目・数十回の選択から推定した傾向にすぎません。
- 結果はブラウザの localStorage にのみ保存され、どこにも送信されません。
- 生成した顔画像の利用条件は、使用した生成サービスの規約に従ってください。
