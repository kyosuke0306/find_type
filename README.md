# 顔の好み診断

2枚の顔から「好きなほう」を選ぶ操作を繰り返して、**自分がどんな顔をタイプだと感じているか**を診断する Web アプリです。

輪郭・目の大きさ・タレ目/ツリ目・眉・鼻・口・髪など **15項目**について、
「どの特徴をどれだけ重視して選んでいたか」と「その特徴のどのあたりが好みか」を推定します。

- **インストール不要** — スマホでもPCでも、ブラウザで開いて写真を選ぶだけ
- **端末内で完結** — 顔の解析も診断も推定もすべてブラウザの中。画像はどこにも送信されません
- ビルド不要（素の HTML + ES モジュール）、外部CDNへの依存もなし
- スマートフォン対応・ダークモード対応

---

## 仕組み

### 1. 顔画像に特徴量を紐づける

「どんな顔が好きか」を言葉で言い当てるには、画像そのものではなく**画像の特徴が数値化されている**必要があります。
そこで取り込み時に [face-api](https://github.com/vladmandic/face-api) で顔検出・68点ランドマーク・年齢/性別推定を行い、
両目間の距離で正規化した幾何量（顔の縦横比、目の開き、目尻の傾き、眉と目の距離、小鼻の幅、唇の厚みなど）と、
画素統計（肌の明るさ、髪の明るさ、髪の長さ）を実測して `data/faces.json` に保存します。

絶対値のままでは「大きい/小さい」の基準が決まらないため、アプリ側で**プール内の順位**に変換し、
すべての特徴を 0.0〜1.0 の相対値にそろえます（`src/features.js`）。

### 2. 選択から好みを推定する

特徴 k について理想値 `m_k` と重視度 `s_k` があると考え、顔 x の好ましさを

```
u(x) = -Σ_k s_k (x_k - m_k)²
```

とする**理想点モデル**を使います。2択の勝率は `P(A) = sigmoid(u(A) - u(B))` で、
これを比較データから MAP 推定します（`src/model.js`）。

単純な重み付き和ではなく理想点モデルを使うのは、

- 「大きすぎても小さすぎても嫌、中くらいが好き」という好みを表現できる
- 重視していない特徴は `s_k` がほぼ 0 に落ちるので、**こだわりの有無を分離できる**

ためです。

### 3. 出す2枚を選ぶ

ランダムに2枚出すと15項目すべてが同時に違ってしまい、どの特徴が効いたのか分離できません。
そこで毎回、候補ペアの中から

- まだ観測の薄い特徴で差がついている
- すでに分かった特徴では差が小さい
- 現在のモデルの予測が五分五分（＝情報量が大きい）
- 同じ顔が出すぎていない

ものを選びます。

シミュレーション（`npm test`）では、この選び方でランダム出題より明確に精度が上がりました。

| 出題方法 | 20回 | 30回 | 45回 |
|---|---|---|---|
| ランダム | 73.6% | 78.5% | 83.6% |
| 適応的（本アプリ） | **77.7%** | **83.0%** | **86.0%** |

数値は、好みを持つ仮想ユーザーに選ばせ、その回答だけから推定したモデルが
**未知のペアで仮想ユーザーの好みを当てられた割合**です（60試行の平均）。

## 使い方

### スマホ・PC どちらでも（インストール不要）

公開されたURLを開き、**「画像を選ぶ」から顔写真を選ぶだけ**です。
顔の検出・切り出し・特徴量の実測はすべてブラウザの中で行われ、
取り込んだ顔は端末内（IndexedDB）にのみ保存されます。**画像はどこにも送信されません。**

**女性の顔24枚を同梱しているので、開いてすぐ診断できます。** 追加で取り込むこともできます。
12枚以上そろうと診断を始められます（片方の性別で12枚必要）。枚数が多いほど精度は上がります。

顔写真は AI 生成のものを推奨します。実在する人の顔を「好み」で採点させることを避けるためと、
知っている顔が混ざると「顔の造作」ではなく「その人への好意」で選んでしまい、診断結果がずれるためです。

生成用のプロンプトは次のコマンドで書き出せます（`prompts-chat.txt` はスマホ向けに、
共通条件を最初に1回送れば以降は1行ずつ送れる形式になっています）。

```bash
npm run generate -- --dry-run --count 24 --female-ratio 1 --out .cache/raw
```

取り込むときのコツ:

- **正面を向いた写真**を選ぶ（大きく傾いていると計測精度が落ちます）
- **背景が無地**だと「髪の長さ」まで測れる（雑多な背景ではこの項目だけ自動で除外されます）
- スクリーンショットではなく**画像そのもの**を使う
- **同じ人の写真は1枚だけ**にする（同一人物が多いと結果が偏ります）

性別は自動で判定しますが、**ショートヘアの女性を男性と誤ることがあります**。
性別が分かっている画像をまとめて取り込むときは、取り込み画面の「取り込む顔の性別」で指定してください。

### PC でまとめて取り込む場合

枚数が多いときは、コマンドで一括処理して結果をリポジトリに同梱できます。
こちらは `data/faces.json` として配信されるので、誰が開いても最初から顔がそろった状態になります。

```bash
npm install
npm run analyze -- --from <画像フォルダ> --debug .cache/debug
npm start   # http://localhost:5173/
```

ブラウザ側と同じ `src/measure.js` を使っているので、実測される特徴量は同じです。

| オプション | 既定値 | 説明 |
|---|---|---|
| `--from` | （必須） | 入力画像フォルダ |
| `--size` | 480 | 書き出す画像の一辺 |
| `--append` | – | 既存の `faces.json` に追加する |
| `--multi` | – | 1枚の画像に写っている顔を全員取り込む |
| `--gender` | – | `female` / `male`。自動判定を使わず全件その性別として扱う |
| `--limit` | 制限なし | 先頭 N 枚だけ処理する |
| `--debug` | – | 検出したランドマークと肌/髪の採取位置を重ねた確認用画像を出力する |

計測が意図どおりか疑わしいときは `--debug .cache/debug` を付けて、
書き出された画像でランドマークと採取位置（水色=頬、黄=髪色、緑枠=髪の走査域、緑線=検出した髪の下端）を目で確認してください。
実行後には項目ごとの実測値のばらつきも表示されます。

### 顔プールが診断に使えるか確かめる

実測値の幅が狭いとき、それが「顔が本当に似ている」のか「測定ノイズに埋もれている」のかは、
数値を眺めるだけでは分かりません。同じ画像を少しずつ違う解像度で解析するとノイズが測れます。

```bash
npm run noise-check -- <画像フォルダ>
```

項目ごとに「顔ごとの差」と「測定ノイズ」を並べて表示します。
比が 3 倍以上あればその項目は診断に使えます。1.5 倍を下回る項目は、
顔の差がノイズに埋もれているので結果を信用できません。

### API で顔を生成する場合

```bash
GEMINI_API_KEY=xxxx npm run generate -- --count 160 --out .cache/raw
npm run analyze -- --from .cache/raw
```

> **Gemini の画像生成には課金の有効化が必要です。**
> 画像生成モデルには無料枠が存在せず（料金表の無料枠欄が「利用不可」）、
> 無料枠のプロジェクトからは `limit: 0` のエラーになって1枚も生成できません。
> AI Studio の画面上での生成は無料ですが、API経由とは別枠です。

| オプション | 既定値 | 説明 |
|---|---|---|
| `--count` | 160 | 生成枚数 |
| `--model` | `gemini-3.1-flash-image` | `--list-models` で利用可能なモデルを確認できます |
| `--image-size` | `0.5K` | 出力解像度。単価に直結します（0.5K なら1枚 $0.045 程度） |
| `--ethnicity` | `japanese` | `japanese` / `eastasian` / `mixed` / `global` |
| `--female-ratio` | 0.5 | 女性の割合 |
| `--dry-run` | – | 課金せずプロンプトだけ書き出す |

`japanese` と `eastasian` では、肌と髪の選択肢が現実的な範囲に差し替わります
（「deep brown skin の日本人」のような矛盾した指定を避けるため）。

## 画像がなくても動作を試す

ダミーの顔プールを作って、アプリの流れだけ確認できます。

```bash
node test/fixture.mjs
npm start
# http://localhost:5173/?data=.cache/fixture
```

`?data=` で顔プールを差し替えられます。

## ファイル構成

```
index.html          画面
styles.css          スタイル
src/features.js     15項目の定義と、プール内順位への正規化
src/measure.js      ランドマークと画素からの特徴量の実測（ブラウザ・Node で共有）
src/model.js        理想点モデルの推定・出題ペアの選択
src/import.js       ブラウザ内での顔検出・切り出し・取り込み
src/store.js        取り込んだ顔の端末内保存（IndexedDB）
src/app.js          画面遷移と診断の進行
vendor/             face-api 本体と学習済みモデル（自前配信・外部CDN不要）
tools/generate.mjs  顔生成、手作業用プロンプトの書き出し
tools/analyze.mjs   PC でまとめて取り込むときの解析
tools/noise-check.mjs 顔プールが診断に使えるかの検証（測定ノイズとの比較）
tools/serve.mjs     依存ゼロの静的サーバー
test/simulate.mjs   仮想ユーザーによる推定精度の検証
test/fixture.mjs    ダミー顔プールの生成
data/faces.json     同梱プールの解析結果（女性24枚）
data/faces/         同梱プールの顔画像（AI生成の架空の顔）
```

## 検証

顔プールを使った通しの動作確認として、特定の特徴だけを基準に選び続ける仮想ユーザーを
ブラウザ上で自動操作させ、その特徴を診断が言い当てられるかを確認しています。

| 選び方 | 診断結果 | 重視度 | 一貫性 |
|---|---|---|---|
| 髪が長いほう | ロング | 93% | 90% |
| 目が大きいほう | ぱっちり目 | 92% | 100% |
| ツリ目なほう | ツリ目 | 94% | 97% |
| 唇が厚いほう | ぽってり唇 | 95% | 100% |
| 面長なほう | 面長 | 93% | 97% |

同梱プールに対する `npm run noise-check` では、15項目すべてで顔ごとの差が
測定ノイズの 4〜85 倍あることを確認しています。

## 注意

- 診断結果はエンターテイメントとして作られたものです。15項目・数十回の選択から推定した傾向にすぎません。
- 結果はブラウザの localStorage にのみ保存され、どこにも送信されません。
- 生成した顔画像の利用条件は、使用した生成サービスの規約に従ってください。
